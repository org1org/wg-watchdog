# WG Watchdog для KeeneticOS

Интерактивный менеджер watchdog-заданий для WireGuard на роутерах Keenetic с установленным Entware.

Для каждого выбранного WireGuard-интерфейса создаётся отдельное задание. Если обычный интернет работает, но внутренний адрес WireGuard-сервера не отвечает на ping, watchdog перезапускает только этот интерфейс штатными командами KeeneticOS через `ndmc`.

## Возможности

- находит WireGuard-интерфейсы Keenetic и показывает их описания;
- поддерживает несколько независимых заданий — по одному на каждый интерфейс;
- позволяет добавлять, изменять, включать, выключать и удалять задания;
- запускает выбранное задание вручную для проверки;
- проверяет адрес WG-сервера во время настройки и позволяет продолжить, если ping временно недоступен;
- отдельно настраивает частоту проверки, число ping-запросов, тайм-аут и задержку перезапуска;
- не перезапускает WireGuard при отсутствии обычного интернета;
- защищает каждое задание от одновременного повторного запуска;
- автоматически устанавливает и запускает `cron`, сохраняя посторонние задания;
- переносит конфигурацию версии 1.0.0 при первом запуске;
- пишет сведения о перезапусках и ошибках в системный журнал.

## Требования

- KeeneticOS 5 или новее;
- установленный и запущенный Entware;
- SSH-доступ к Entware от пользователя `root`;
- WireGuard-интерфейс, настроенный средствами KeeneticOS;
- внутренний адрес WG-сервера, который обычно отвечает на ping через туннель.

## Установка и управление одной командой

Подключитесь к Entware по SSH от `root` и выполните:

```sh
wget -qO- https://raw.githubusercontent.com/org1org/wg-watchdog/main/install.sh | sh
```

При первом запуске установщик создаст первое задание. При повторном запуске той же команды он обновит файлы программы и откроет меню существующих заданий.

После установки менеджер также можно запускать локально:

```sh
/opt/bin/wg-watchdog-manager
```

## Параметры задания

Для каждого числового параметра можно нажать Enter и принять предлагаемое значение.

| Параметр | По умолчанию | Назначение |
| --- | ---: | --- |
| `CHECK_INTERVAL` | `5` | Частота проверки в минутах, от 1 до 59 |
| `PING_COUNT` | `3` | Число ping-запросов при одной проверке |
| `PING_TIMEOUT` | `3` | Ожидание каждого ответа, секунд |
| `RESTART_DELAY` | `3` | Пауза между выключением и включением интерфейса, секунд |

## Где хранятся файлы

- `/opt/bin/wg-watchdog-manager` — интерактивный менеджер;
- `/opt/bin/wg-watchdog.sh` — исполнитель проверки;
- `/opt/etc/wg-watchdog.d/WireguardN.conf` — отдельные настройки каждого интерфейса;
- `/opt/etc/crontab` — автоматически управляемые строки запуска;
- `/opt/etc/crontab.wg-watchdog.bak` — резервная копия crontab перед последним изменением;
- `/opt/var/run/wg-watchdog-WireguardN.pid` — временная блокировка параллельного запуска.

Конфигурация содержит только адреса и числовые параметры, но на всякий случай сохраняется с правами `600`.

## Проверка работы

Посмотреть задания и их состояние:

```sh
/opt/bin/wg-watchdog-manager
```

Принудительно проверить конкретное задание, даже если оно отключено:

```sh
/opt/bin/wg-watchdog.sh --job Wireguard0 --force
```

Посмотреть журнал и созданные строки cron:

```sh
logread | grep wg-watchdog
grep -A20 'BEGIN WG-WATCHDOG' /opt/etc/crontab
```

## Обновление с версии 1.0.0

Снова выполните команду установки. Если существует старый файл `/opt/etc/wg-watchdog.conf` и ещё нет новых заданий, менеджер автоматически перенесёт его в `/opt/etc/wg-watchdog.d/` и сохранит исходник как `/opt/etc/wg-watchdog.conf.migrated-v1.0.0`.

## Отключение и удаление

Отключённое задание остаётся в меню со всеми настройками, но его строка удаляется из cron. Пункт «Удалить» удаляет конфигурацию выбранного задания.

Для полного ручного удаления программы сначала удалите задания через менеджер, затем выполните:

```sh
rm -f /opt/bin/wg-watchdog.sh /opt/bin/wg-watchdog-manager
rm -rf /opt/etc/wg-watchdog.d
/opt/etc/init.d/S10cron restart
```

Пакет `cron` не удаляется, поскольку он может использоваться другими программами Entware. Перед полным удалением при необходимости восстановите собственный crontab из `/opt/etc/crontab.wg-watchdog.bak`.

## Как принимается решение о перезапуске

Сначала watchdog проверяет обычный доступ в интернет через `1.1.1.1` и `8.8.8.8`. Если оба адреса недоступны, интерфейс не перезапускается. Если интернет доступен, но внутренний адрес WG-сервера не отвечает, выполняются команды `interface WireguardN down` и `interface WireguardN up` с заданной паузой.

Из-за этого сервер должен отвечать на ICMP через туннель. Если ICMP на сервере намеренно запрещён, текущий метод контроля использовать нельзя.
